Load a hunt into Splunk (your SOC lab)
  1. Settings → Indexes → New Index: create the index named in the hunt (for example hunt_phish).
  2. Settings → Add Data → Upload: choose the hunt's .json file.
  3. Source type: _json. Under Timestamp → Advanced set the time zone to GMT/UTC — all times in these files are UTC.
  4. Index: the hunt's index → Review → Submit.
  5. Verify: with the time picker on All time, index=hunt_phish | stats count must give the same number of events as the hunt card.

Which check passed?

30

One email check PASSED for the phish. Which one? (spf, dkim or dmarc)

format: spf, dkim or dmarc

Hint

Open one phish event and read the three fields spf, dkim, dmarc.

SPF passed. The attacker owns novacart-payroll.com, so their own server is allowed to send for it. A pass only proves the server may send for that domain — it does not prove the domain is honest. DKIM and DMARC were none.

Switch to the proxy: log_type=web_proxy dest_host=novacart-payroll.com | stats dc(user)

4 users: r.saad, m.fawzy, h.ali and k.adel. Opening the page is a click — not yet a stolen password.

First password lost

30

Who was the FIRST user to submit the fake login form?

format: username

Hint

Sending a form is a POST. Look at method=POST to the phishing domain and read the times.

m.fawzy at 08:44:38. The site then redirected to the real ERP, so the user saw nothing strange.
Impact

Too late?

30

Another user submitted the form later — after the SOC got the report. Who?

format: username

Hint

Same POST search. Compare the time with the report time (08:52).

k.adel at 13:09:19 — four hours after the report. The domain was never blocked. Lesson: block the domain and purge the mail as soon as you confirm the phish.
Detect

Proxy category

20

Which category did the proxy give the phishing site?

format: category name, as written in the log

Hint

Read the category field of the proxy events for that domain.

newly_registered. A POST to a newly registered domain is a strong, cheap detection rule.
Debrief — the full story (open after you finish)
Attack

A look-alike domain sends a payroll email to 42 people. The link opens a fake login page that sends people back to the real ERP after they type their password.

Logs

Mail gateway (sender, sender_ip, SPF/DKIM/DMARC, url_domain) and web proxy (user, dest_host, method, category).

Detection

Alert on a POST to a newly_registered domain, and on external senders whose domain contains our brand name.

Investigation

Scope the recipients → find who opened the link → find who submitted the form (POST) → check their later logons.

Response

Block the domain and both IPs. Purge the email from all 42 mailboxes. Reset the passwords and end the sessions of m.fawzy and k.adel. Thank f.nabil.

Attack

Password spraying against RDP on an internet-facing jump server, two rounds (01:12 and 01:29). One admin password works; the attacker creates svc-backup2 and adds it to IT-Remote-Access.

Attack
