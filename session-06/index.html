    Bridging the gap — from detection to analysis

    Detection decides if we care. Analysis finds out what really happened.

    Night 3 · the analysis pathNC-S6-01 · LNX-DB01 · a new account joined sudo · picked up 02:20
    1Detect2First response3Deep analysis4Evidence5Endpoint6Logs7Report
    Ask the room

    A museum alarm rings at night. What do the guards do before they call the police?

    Show the answer

    They check: is it real, which room, what is missing, is the thief still inside? Then they call — with facts. That checking is analysis.

    What INE says
    • Detection answers: "Something suspicious just happened, do we care?"
    • When a Tier 2 analyst or responder says "yes", the work pivots to analysis: what happened, how far it spread, how to stop it.
    • Analysis starts the moment an escalated alert is accepted as credible.
    Detection asks

    Do we care? One rule, one event, one score. NC-S6-01: "a user joined sudo on LNX-DB01".

    Analysis asks

    What · how · where · how far? Who used svc_sync, from where, what came next — on which hosts.

    Analysis phaseterm
    Definition
    The disciplined investigation that begins when an escalated alert is accepted as a credible security event (INE).
    Why it exists
    To remove uncertainty: kill false positives, confirm true ones, find what detection missed.
    Where used
    NIST Detection & Analysis — the Tier 2 / responder's job.
    Example
    A guard replays the CCTV before calling the police.
    SOC example
    You take NC-S6-01 at 02:20 and rebuild what happened on LNX-DB01 and around it.

    S06 · P07Theory + practice⏱ 6 min

    Pivoting through logs

    One artefact opens the next search. That loop is how a single alert becomes a full picture.

    Night 3 · the analysis pathorient → re-run ±5 min → scope → decide → notify
    1Detect2First response3Deep analysis4Evidence5Endpoint6Logs7Report
    Ask the room

    The alert gives you one host and one minute. How do you find the rest of the story?

    Show the answer

    Pick one artefact from the alert, search ±5 minutes around it, and turn each new value into the next search. That loop is pivoting.

    What INE says
    • Start with one piece of evidence in your logs: an IP address, a process hash, a username, a file path, a URL.
    • Use it as a pivot point to discover related events that broaden the picture of the incident.
    • Pivoting also uncovers silent false negatives — what no rule caught.
    Pivot pointterm
    Definition
    A value from one event (IP, user, hash, path) that you search for in other events or other logs.
    Why it exists
    Attackers leave the same value in many places; each place adds a piece.
    Where used
    Every investigation step after the first search.
    Example
    A hash from one host searched across the whole fleet.
    SOC example
    The source address of svc_sync's login on LNX-DB01 tells you which host to search next.

    Explorer task 1 — one pivot

    Task

    Find svc_sync's logins on LNX-DB01 and where they came from. Then run the second example: the lookup names the source.

      Evidence triage — value × volatility

      You cannot grab everything at once. Score each item, then collect the highest total first.

      Night 3 · the analysis pathvalue + volatility → volatile → logs → disk → hash + custody → validate

      Ask the room

      Show the answer

      The memory. It disappears at reboot; the disk waits. Score both on value and volatility — the higher total goes first.

      What INE says
      • Triage = what to collect and in which order, under time pressure.

      Ask the room

      You copied the memory image to a share. How will you prove it never changed?

      Show the answer

      Hash it at capture, log every hand-off, re-hash before you analyse it. Same hash, same evidence — that record is the chain of custody.

      What INE says
      • Collection captures a full, defensible copy of every artefact found in triage.
      • It answers: the cause, how the attack unfolded, what was accessed or changed, and whether data was stolen.
      • Always hash, log and secure every artefact at once — that preserves the chain of custody.
      Chain of custodyterm
      Definition
      A log of who collected, moved and held each item: what, when, where and its hash (INE).
      Why it exists
      So every item stays legally and technically defensible (INE).
      Where used
      Every hand-off: capture → evidence share → analyst → court or regulator.
      Example
      INE: sha256sum mem.raw > mem.raw.sha256, recorded in the ticket.
      SOC example
      LNX-DB01's memory image: hashed at capture, logged in the ticket, re-hashed on the share — same hash, same evidence.
