    What lives in RAM

    Modern attackers use fileless techniques and in-memory payloads that leave little or no trace on disk. Memory shows the system at the very moment of compromise.

    Memory forensicsterm
    Definition
    Capturing, analysing and interpreting the contents of volatile system memory (RAM) for investigation or incident response.
    Why it exists
    RAM holds data that may never touch the disk — lost at shutdown or reboot.
    Where used
    Fileless malware, injected code, credential theft, live C2 — anything a disk scan misses.
    Example
    A PowerShell process with injected code and an open connection to a C2 server.
    SOC example
    "EDR says clean" is not the end of the case when the network still sees beaconing.
    What memory forensics entails
    1. Acquisition — FTK Imager, DumpIt, Belkasoft RAM Capturer, WinPmem.
    2. Preservation & verification — SHA-256, chain of custody.
    3. Analysis — processes, drivers, connections, handles, injected code, credentials.
    4. Interpretation & reporting — timeline, narrative, IOCs into detection.
    Tools

    Volatility / Volatility 3 — the most widely adopted framework · Rekall — a fork · Redline — GUI with IOC scanning · Belkasoft RAM Capturer, DumpIt — acquisition · LiME — Linux acquisition.

    Keep this

    Processes · connections · commands · credentials · drivers · clipboard · unpacked code · hives. If it ran, memory saw it.

    S10 · P06Tool⏱ 14 min

    Volatility — plugins that read memory

    An open-source Python framework. Each plugin extracts one kind of evidence from a memory image.

    Volatilitytool
    Definition
    An open-source memory-forensics framework for Windows, Linux and macOS images, built around plugins.
    Why it exists
    A memory image is raw bytes; Volatility maps them back to processes, sockets, registry keys and more.
    Where used
    IR and forensic teams worldwide; widely cited in court cases.
    Example
    vol -f memdump.mem windows.pstree
    SOC example
    From one dump: the parent of the bad process, its command line, its connection, its injected code.
    Volatility 2Volatility 3
    LanguagePython 2.7 (legacy)Python 3, rewritten
    OS mappingProfiles chosen by hand (imageinfo → --profile=Win10x64_…)Symbol tables, found automatically
    Syntaxvol.py -f img --profile=P pslistvol -f img windows.pslist
    Pluginsmore community pluginsfewer, but modular and easier to extend
    Speedslower on large dumpsfaster, more efficient
    Use it forold systems (XP, 2003), INE's Lab 12new cases — the actively developed version
    Why profiles matter (Volatility 2)

    Each OS, version and architecture stores processes, DLLs and kernel objects differently. Without the right profile, Volatility cannot map raw offsets to meaningful structures. Volatility 3 solves this with symbol tables — on first use it may download them, so an offline lab needs them pre-loaded.

    The plugins you will use

    Volatility 3 (Volatility 2)PurposeUse case
    windows.info (imageinfo)OS, build, symbolsKnow the system before you analyse
    windows.pslist · pstree · psscan (+ psxview)Running and hidden processesOdd parents, hidden or terminated processes
    windows.cmdline (cmdline · cmdscan · consoles)Command lines, console historyWhat the attacker typed
    windows.netscan (netscan)Connections and socketsC2, lateral movement
    windows.dlllist (dlllist · ldrmodules)Loaded DLLsInjected or unusual libraries
    windows.malfind (malfind)Suspicious memory regionsCode hidden in legitimate processes
    windows.svcscan (svcscan)ServicesMalicious services
    windows.registry.hivelist · printkeyHives and keys in memoryRun keys, persistence
    windows.hashdump · lsadumpCredential materialProving credential theft
    yarascan · timeliner · filescan · dumpfilesSignatures, timeline, filesKnown malware, chronology, extraction
    ▶ Which plugin answers the question?

    Pick a question.

    windows.pstree

    Parent → child tree with PIDs and start times. Look for Office or browsers starting shells, and shells starting network tools.

    windows.psscan (V2: psxview)

    Scans memory for process structures, so it finds processes unlinked from the normal list. A process in psscan but not in pslist deserves a look.

    windows.netscan

    Local and remote address, state, PID and owner. Filter for the IP from your alert, then pivot to that PID.

    windows.malfind

    Memory that is executable and writable and not backed by a file. Expect some noise from security software and JIT engines (INE's lab: MsMpEng, SearchUI) — judge each hit by its process.

    windows.cmdline (V2: cmdscan, consoles)

    The full command line of every process; V2's consoles also recovers console input and output.

    windows.registry.printkey · svcscan

    Read Run keys and services straight from memory — the same persistence you hunt in Part 3.

    Injection.

    Keep this

    info → pstree/psscan → cmdline → netscan → malfind → registry. Each answer is the next pivot.

    How a PDF can carry a script

    PDFs are everywhere — in business, government and personal mail. That makes them a favourite phishing attachment.

    PDF objectterm
    Definition
    A PDF is a collection of numbered objects — catalog, pages, fonts, content streams, actions — linked together and indexed by a cross-reference table.
    Why it exists
    Objects let a reader find and render any part of a document quickly.
    Where used
    Every PDF. Some objects define behaviour: actions on open, forms, scripts.
    Example
    /OpenAction in the catalog points to an object that holds /JavaScript.
    SOC example
    A CV with /OpenAction + /JS has no business reason to exist — escalate it.
    pdfid — quick triage

    Counts suspicious keywords without fully parsing the file: /JavaScript, /JS, /OpenAction, /AA, /Launch, /EmbeddedFile, /AcroForm, /ObjStm.

    pdfid.py suspicious.pdf
    pdf-parser — deep look

    Finds and extracts objects, dumps scripts for review, decodes compressed streams.

    pdf-parser.py --stats suspicious.pdf
pdf-parser.py -s /JavaScript suspicious.pdf
pdf-parser.py -o 7 -f -w suspicious.pdf
    pdfid keywordMeansNormal in a CV?
    /JS · /JavaScriptEmbedded scriptNo
    /OpenAction · /AASomething happens automaticallyRarely
    /LaunchStarts external contentNo
    /EmbeddedFileA file inside the PDFRarely
    /ObjStmObjects hidden inside compressed streamsSometimes — but it can hide the others
    Keep this

    pdfid to triage → pdf-parser to extract → never open in a normal reader.

    Macro-enabled documents are still one of the most common initial-access vectors. olevba reads the macros without running them.

    VBA macroterm
    Definition
    A small program written in Visual Basic for Applications, built into Word, Excel and PowerPoint to automate tasks.
    Why it exists

    Where used

    SOC example

    oletools

    S10 · P15Theory⏱ 15 min

    Anatomy of a Portable Executable

    Most Windows malware arrives as a PE file. Its headers tell you what it is, when it was built, and what it can do — before it ever runs.

    Portable Executable (PE)term
    Definition
    The standard Windows format for executables, object code and DLLs: headers and sections that tell Windows how to load and run the program.
    Why it exists
    One format for every Windows program, so the loader knows where code, data, imports and resources are.
    Where used
    .exe, .dll, .sys drivers — and disguised files with an MZ header (Session 9).
    Example
    An import of WriteProcessMemory suggests the program can write into other processes.
    SOC example
    Static PE triage tells you whether a sample is worth sandbox time — and gives IOCs (hash, compile time, imports).
    Red flagWhy it matters
    Imports like VirtualAlloc, WriteProcessMemory, CreateRemoteThreadCapability to inject into other processes
    Very few imports + high-entropy sectionsPacked — the real imports are resolved at run time
    Virtual size much larger than raw sizeUnpacks itself in memory
    Non-standard section namesPackers and custom tooling
    Entry point outside .text, TLS callbacksCode that runs before the main program, or obfuscation
    ASLR / DEP turned offSecurity features disabled on purpose
    No or invalid digital signature on a "Microsoft" fileMasquerading
    Debug path in the debug directoryCan leak the author's build environment
    pestudio

    Static triage in one window: headers, compile time, entry point, imports and exports, flagged APIs, sections, resources, strings, signature, indicators — nothing is executed.

    CFF Explorer

    A detailed PE viewer and editor: every header field, import and export directories, section headers, a hex view, signature checks — good for learning the structure.

    Keep this

    Headers say what and when · imports say what it can do · sections say whether it hides.

    S10 · P19Theory⏱ 8 min

    Hives — and the files behind them

    The registry looks like one tree in regedit. On disk it is a handful of files called hives — and those files are your evidence.

    Windows Registryterm
    Definition
    A hierarchical database of low-level settings for Windows, applications, users and hardware — thousands of keys and values.
    Why it exists
    One central place for configuration that the OS and programs read and write constantly.
    Where used
    Everywhere: services, drivers, startup, users, devices, recent activity.
    Example
    HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run starts programs at boot.
    SOC example
    Attackers use it for persistence, to disable security tools and to change system behaviour (Session 7's Run-key event).
    Dirty hives

    Each hive has transaction logs (.LOG1, .LOG2) beside it. Recent changes may still sit in the logs. Collect them with the hive; Registry Explorer will offer to replay them.

    Tools

    Registry Explorer (Eric Zimmerman) — GUI, bookmarks, data interpreter · RegRipper — plugins that pull known artefacts into a text report · hivex — Linux library and tools · DCode — converts timestamps.

    Keep this

    SYSTEM · SOFTWARE · SAM · SECURITY in config\ — NTUSER.DAT in each profile — always with their .LOG files.

    Keys that profile a system — and a user

    First the system: what is it, which time zone, which network. Then the user: who, what they opened, what they ran, what they plugged in.

    First: which control set?

    SYSTEM holds ControlSet001, sometimes ControlSet002. SYSTEM\Select → Current tells you which one was in use. Read that one.

    ▶ Decode what you find

    Three values look like nonsense until you know the encoding.

    UserAssist · value name
    raw      {1NP14R77-02R7-4R5Q-O744-2RO1NR5198O7}\abgrcnq.rkr
ROT13    {1AC14E77-02E7-4E5D-B744-2EB1AE5198B7}\notepad.exe
    • ROT13 shifts every letter by 13 (a↔n, b↔o …). The GUID is the System32 known folder. Registry Explorer and RegRipper decode it for you — plus the run count and last run time.
    SOFTWARE\Microsoft\Windows NT\CurrentVersion
    InstallDate  REG_DWORD  0x68C6A2F0  (1757848304)
decoded      2025-09-14 11:11:44 UTC
    • A Unix epoch: seconds since 1970-01-01 UTC. DCode, Registry Explorer's data interpreter or date -u -d @1757848304 convert it.
    SYSTEM\ControlSet001\Control\Terminal Server
    fDenyTSConnections  REG_DWORD  0
    • The name is a double negative: deny = 0 means RDP connections are allowed. Compare with 4624 type 10 events (Session 7).
    NTUSER\Software\Microsoft\Windows\CurrentVersion\Run
    OneDrive    REG_SZ  "C:\Users\a.hassan\AppData\Local\Microsoft\OneDrive\OneDrive.exe" /background
WinUpdate   REG_SZ  C:\ProgramData\update.exe
    • Same reading as Session 7: the second value imitates Windows Update and runs from ProgramData. The key's last-write time tells you when it changed.
