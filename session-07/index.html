    Providers, channels and collection

    Three words explain where every Windows event comes from and where it goes.

    Providerterm
    Definition
    A software component that generates log events — and defines their structure and content.
    Why it exists
    Each part of Windows (and each tool) knows its own activity best, so each writes its own events.
    Where used
    Every event names its provider: Microsoft-Windows-Security-Auditing, Microsoft-Windows-Sysmon, Microsoft-Windows-PowerShell.
    Example
    Security-Auditing writes 4624 every time someone logs on.
    SOC example
    A Sigma rule or a SIEM search often filters on the provider first — it tells you who is speaking.
    Channelterm
    Definition
    A log stream where providers publish their events — think of it as a log file or container for one kind of event.
    Why it exists
    To keep different kinds of events apart, with their own size, retention and access rights.
    Where used
    Event Viewer shows channels as the tree: Windows Logs → Security, Applications and Services Logs → Microsoft → Windows → Sysmon → Operational.
    Example
    On disk each channel is a file in C:\Windows\System32\winevt\Logs\ — for example Security.evtx or Microsoft-Windows-Sysmon%4Operational.evtx (%4 stands for /).
    SOC example
    When you collect evidence, you export channels — not "the logs".
    Channel typeWhat it holdsFor IR
    AdminHigh-level operational events for troubleshootingSometimes useful
    OperationalDetailed events used for auditing and monitoringMost IR value — Sysmon, PowerShell, TaskScheduler, WMI-Activity are all Operational
    AnalyticHigh-volume, fine-grained events — off by defaultTurned on only for deep troubleshooting
    DebugDeveloper-focused, very low-level detailRarely
    Why this matters in an incident

    A local EVTX can be overwritten (rollover) or cleared (1102). A forwarded copy cannot be touched by the attacker on the host. In page 3's story, WEF is the reason the case survived.

    Keep this

    Provider writes → channel collects → EVTX stores → forwarder protects.

    The five key channels for DFIR

    Each one gives a piece of the puzzle. Together they show the attacker's behaviour.

    PowerShell/Operational · 4104

    Script block logging records the code after PowerShell decodes it — -enc does not hide it here.

    TaskScheduler/Operational · 106, 200/201

    106 when the task was registered, 200/201 every time it starts. Security 4698 also records task creation when that audit policy is on.

    Consumer creation and binding show WMI persistence — quiet, and easy to miss.

    High-value Windows event IDs every responder should know

    A Windows network writes millions of events a day. Knowing which IDs matter is how you cut through the noise.

    Authentication & logon
    4624Successful logon — who, and how (type 2 local · 3 network · 10 RDP)
    4625Failed logon — brute force, credential stuffing
    4648Logon with explicit credentials — often in pass-the-hash / pass-the-ticket
    4675SIDs were filtered — logon with added SIDs (privilege abuse)
    Accounts & privileges
    4720User account created — unusual new accounts = persistence
    4722User account enabled — a dormant account comes back
    4723 · 4724Password change / reset — compromise or lateral movement
    4732 · 4756Member added to a security group — privilege escalation
    4670Permissions on an object changed — e.g. admin groups
    Services, tasks & object access
    7045New service installed (System) — common persistence
    4697Service installation (Security)
    106Task created (Task Scheduler) — persistence or payload execution
    4663Object accessed — sensitive files or keys (needs auditing set up)
    4656Handle to an object requested — comes before 4663
    Logoff & sessions
    4634Logoff — pair with 4624 for the session length
    4647User-initiated logoff — user vs system actions
    4778 · 4779RDP session reconnect / disconnect — trace remote access
    Two more you will meet today

    4688 — a new process was created (Security). Without the "include command line" policy it shows that a process started, but not what it ran — which is why responders deploy Sysmon. 1102 — the audit log was cleared. Two more logon types: 5 = service, 7 = unlock — both appear in today's case as normal background.

    How Sysmon works

    A kernel driver watches, a service writes, a configuration decides what is worth keeping.

    Sysmon (System Monitor)term
    Definition
    A free, lightweight tool from Microsoft's Sysinternals suite. It runs in the background as a Windows service and logs system activity to Applications and Services Logs → Microsoft → Windows → Sysmon → Operational.
    Why it exists
    Standard Windows logs miss what responders need most: full command lines, parent processes, hashes, network connections per process.
    Where used
    Security monitoring, threat hunting, incident response, behavioural analysis, forensic investigation.
    Example
    Event ID 1 shows powershell.exe -nop -w hidden -enc … with its parent WINWORD.EXE.
    SOC example
    "Word started PowerShell" is one Sysmon event — and one of the strongest phishing signals there is.
    Why responders value it (INE)
    • 1Visibility into low-level OS behaviour without kernel debugging.
    • 2Correlated data — processes, network and registry linked into one story.
    • 3Lightweight and customisable — low footprint, configs reduce noise.
    • 4Persistent logs — forwarded Sysmon survives a cleared log on the host.
    • 5Advanced threats — odd parent-child pairs, PowerShell abuse, lateral movement.
    Three commands
    Sysmon64.exe -accepteula -i config.xml   # install with a config
Sysmon64.exe -c config.xml               # load a new config, no reinstall
Sysmon64.exe -u                          # uninstall

    Popular community configs: SwiftOnSecurity sysmon-config · Olaf Hartong sysmon-modular.

    No config = a wrong answer later

    Without a good configuration Sysmon is either far too noisy or misses what you need. If an event you expect is missing, check the config before you conclude "it never happened".

    Keep this

    Driver hooks → service formats and hashes → config filters → Event Log → any forwarder.

    Sysmon event IDs that matter

    Six IDs carry most of the value. Learn what each one gives you as an IOC.

    ID 1 · Process create

    Image path, command line, parent, hash. The backbone of every Windows timeline.

    ID 3 · Network connection

    Source and destination IP and port, plus the process GUID — who called out, and where.

    ID 11 · File create

    Target file name — payloads dropped to disk.

    ID 13 · Registry value set

    Key path and new data — Run keys and other autostarts.

    ID 22 · DNS query

    Query name and PID — which process resolved which domain.

    ID 23–24 · File delete · clipboard

    Signs of data being gathered before theft, or of exfiltration.

    Export event logs with wevtutil

    Before you analyse, take a safe copy. Event logs roll over — and attackers clear them.

    wevtutiltool
    Definition
    The Windows Events command-line utility, built into every Windows version. It lists, queries, exports and clears event logs.
    Why it exists
    Event Viewer is a GUI on one machine. wevtutil can be scripted, run remotely and run in a live-response session.
    Where used
    Evidence collection: INE's "secure transient logs" step — export 24–48 h of Sysmon, Security and PowerShell before rollover.
    Example
    wevtutil epl Security C:\IR\Security.evtx
    SOC example
    The first command a responder runs on a suspicious host — before anything gets overwritten.
    CommandWhat it does
    wevtutil elLists every log (channel) on the host
    wevtutil gli SecurityLog information: size, record count, oldest record
    wevtutil qe Security /c:5 /rd:true /f:textQueries the 5 newest events as text
    wevtutil epl Security C:\IR\Security.evtxExports the channel to a file
    wevtutil epl Security C:\IR\4720.evtx /q:"*[System[(EventID=4720)]]"Exports only the events that match an XPath query
    wevtutil cl <log>Clears a log — never on evidence. This is what produces 1102 (T1070.001).

    Hunt with Chainsaw and Sigma

    Timeline Explorer is your eyes. Chainsaw is a thousand rules reading the same logs in seconds — written in Sigma, the shared language of detections.

    Sigmaterm
    Definition
    An open, generic format for log detection rules, written in YAML. One rule describes what to look for, independent of any SIEM.
    Why it exists
    Every SIEM has its own query language. Sigma lets the community write a detection once and convert it to SPL, KQL, Elastic and more.
    Where used
    The SigmaHQ repository holds thousands of rules; SOCs import, tune and convert them; Chainsaw runs them directly on EVTX.
    Example
    "Office application starts PowerShell" — the rule below.
    SOC example
    A threat report publishes a Sigma rule → you convert it to SPL and search your whole estate the same day.

    Anatomy of a Sigma rule

    office_spawns_powershell.yml · our rule
    title: Office Application Starts PowerShell
id: 6f1c2a3e-7b4d-4c8e-9a51-2d0e8b7f4c10
status: experimental
description: Detects Word, Excel or PowerPoint starting PowerShell - a common sign of a malicious document.
author: ITGate eCIR
date: 2026-10-07
logsource:
    product: windows
    category: process_creation
detection:
    selection_parent:
        ParentImage|endswith:
            - '\WINWORD.EXE'
            - '\EXCEL.EXE'
            - '\POWERPNT.EXE'
    selection_child:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
    condition: selection_parent and selection_child
falsepositives:
    - Rare legitimate macros that call PowerShell
level: high
tags:
    - attack.execution
    - attack.t1059.001
    ▶ Click a part of the rule

    Five blocks. Learn what each one does.

    Metadata

    A human title, a unique id (UUID) so tools can track the rule, and a status (experimental → test → stable) that tells you how much to trust it.

    logsource — which data

    product: windows + category: process_creation means "process-creation events": Sysmon ID 1 or Security 4688. The converter or Chainsaw's mapping file turns this into real channels and field names.

    detection — named selections

    Each selection is a set of field conditions. |endswith is a modifier (others: |contains, |startswith, |re). Values in a list are joined with OR.

    condition — the logic

    Combine selections with and, or, not, 1 of selection_*. Here: an Office parent and a PowerShell child.

    Triage help

    falsepositives tell the analyst what to rule out · level (informational → critical) sets severity · tags map to ATT&CK. This is the same rule → alert → triage chain from Session 5.
