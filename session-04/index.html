    What Splunk is

    A SIEM and a data analytics platform in one — INE's words. A simpler picture: a giant search engine for your machine data. Four kinds of data go in; four kinds of question come out.

    What INE says

    Splunk is a SIEM and data analytics platform that collects, indexes and analyses machine data in real time. Think of it as a giant search engine for your machine data. It collects operating system logs (Windows Event Logs, Linux syslog), security device telemetry (firewall, IDS/IPS, antivirus), application logs (web servers, databases, APIs) and cloud logs (AWS, Azure, GCP). Its use cases: IT operations monitoring, security monitoring, business intelligence, compliance.

    Splunkterm
    Definition
    A platform that collects, indexes and searches machine data — logs and events from any system — in real time.
    Why it exists
    Logs live on hundreds of machines in dozens of formats. One place to search them all is the only way to answer "what happened?" in minutes.
    Where used
    SOCs (as a SIEM, with Enterprise Security), IT operations, and anyone who must prove what happened and when.
    Example
    A web team searches status=500 over the last hour to find a broken page.
    SOC example
    NovaCart searches index=nc_linux "Failed password" and finds the 17 guesses against svc_report in one second — the night, in one line.
    Machine dataterm
    Definition
    Everything a machine writes about what it is doing: logs, events, metrics, configuration changes, traffic records.
    Why it exists
    Every program leaves a trace. Those traces are the only evidence of what really happened on a system.
    Where used
    The input of every SIEM. Session 3's eight-stage pipeline moves it; Splunk indexes it.
    Example
    One Apache line: who asked for which page, when, and what the server answered.
    SOC example
    FW01 wrote 73 CEF lines that night. 30 of them point at WEB01 — the only evidence WEB01 was attacked, because WEB01 itself kept nothing.
    SPL — Search Processing Languageterm
    Definition
    Splunk's search language: a filter, then commands joined by pipes |, each command changing the results of the one before.
    Why it exists
    A search box that only matches words cannot count, sort, group or compare. SPL turns "find the lines" into "answer the question".
    Where used
    Every search, report, alert and dashboard panel in Splunk is SPL underneath.
    Example
    index=nc_web status=404 | stats count by clientip | sort -count — who gets the most "page not found" errors.
    SOC example
    index=nc_wineventlog EventCode=4625 | stats count by Account_Name | sort -count — INE's own example (slide 161): which accounts fail to log on most. On the night it lists the 12 sprayed names.
    ↺ From Session 3

    Splunk sits at stages 5–8 of the log pipeline: parse → store → analyse → alert. Its forwarders are the shippers of stage 3 ("forwarder = shipper, e.g. Splunk UF" — the 16 terms). Nothing new in the pipeline — only new names for the parts.

    Keep this

    Splunk = collect + index + search, in real time, for any machine data. SIEM and analytics platform in INE's words; a search engine for logs in yours.

    How Splunk works — ingest, index, search

    Three jobs, three roles. The forwarder ships, the indexer parses and stores, the search head asks. In a big company they are separate servers; in our lab two of them share SOC01.

    What INE says

    1 · Data ingestion. Data comes from servers, network devices, applications, cloud services and security tools. A Universal Forwarder (UF) is a lightweight agent that only forwards data. A Heavy Forwarder (HF) can parse and index data before sending it. 2 · Indexing. Parsing breaks raw data into events, applies timestamps and extracts key-value pairs; indexing stores the events in time-series indexes for fast retrieval. 3 · Search and visualisation. SPL searches filter, correlate and analyse; dashboards show real-time visuals; alerts fire on thresholds — e.g. "failed logins > 10 in 5 minutes".

    Forwarder — UF and HFterm
    Definition
    The agent on the host that sends data to the indexer. Universal = lightweight, forwards only. Heavy = a full Splunk that can parse, filter and route before sending.
    Why it exists
    Logs are born on the host; something must carry them off it — reliably, over one port, with buffering if the indexer is down.
    Where used
    A UF on every server; an HF in front of a data centre or a noisy source that needs filtering first.
    Example
    INE Lab 1 installs a UF on DC01 (Security log + AD) and on LINUX01 (auth.log).
    SOC example
    After the night, NovaCart puts a UF on WEB01 first — the host that had no agent. One week later it is the host that catches the attacker's return.
    Indexer and indexterm
    Definition
    The indexer parses incoming data into events and stores them. An index is the store itself: a named collection of events on disk, searched by time.
    Why it exists
    Searching raw text files is slow and blind. Indexed events have a time, fields and a name — the three things every search starts with.
    Where used
    One index per kind of data or per team, so access, retention and searches stay clean.
    Example
    INE searches index=* — every index. We create nc_wineventlog, nc_linux, nc_fw, nc_web.
    SOC example
    An index that does not exist on the indexer means events silently dropped — a lesson from our real build. Create the index before you point a forwarder at it.
    Search headterm
    Definition
    The Splunk role that takes your SPL, asks the indexers, merges the answers and shows them — plus dashboards and alerts.
    Why it exists
    Searching and storing are different workloads. Separating them lets one search head ask many indexers at once.
    Where used
    Splunk Web (port 8000) is the search head's face. In our lab it is on SOC01.
    Example
    The Search & Reporting app, the time picker, the fields sidebar — page 14.
    SOC example
    The IR lead's four questions are answered on the search head. The indexers only hold the data; the search head holds the conversation.
    Sourcetypeterm
    Definition
    The label that tells Splunk what format the data has: where events begin and end, where the timestamp is, which fields to extract.
    Why it exists
    A web log, a Windows event and a CEF line look nothing alike. Without the sourcetype, parsing guesses — and ten lines end up in one event.
    Where used
    Set on the forwarder's input (sourcetype = syslog) or chosen in Add Data. Every event carries it.
    Example
    access_combined for Apache, syslog for auth.log, WinEventLog:Security for the Windows Security log.
    SOC example
    The Windows export is one event per several lines. With the right sourcetype the indexer keeps them together; with the wrong one, Account_Name never becomes a field.
    Every event carries five fields

    _time (when) · host (where it came from — JUMP01, WEB01) · source (the file or channel — /var/log/auth.log, WinEventLog:Security) · sourcetype (its format) · index (where it lives). Filter on these first — every time. Page 19 makes this the rule.

    Editions — and Enterprise Security

    INE names two editions: Free and Enterprise. On its own Splunk is a search platform; Enterprise Security (ES) is the premium app that turns it into a full SIEM for a SOC. Which one are we running — and why?

    What INE says

    Splunk Free: a single user, up to 500 MB/day of indexing, no authentication or role-based access — for testing and personal learning. Splunk Enterprise: unlimited indexing (by licence), clustering and distributed search, role-based access control, all apps and premium solutions — for medium to large enterprises. Enterprise Security adds six things: security posture dashboards · correlation searches · risk-based alerting · a threat-intelligence framework · incident review and workflows · MITRE ATT&CK integration.

      Definition
      A search is a chain: the first part selects events; each | passes the current results to the next command, which changes them.

      rex · named groupterm
      Definition
      rex extracts fields at search time with a regular expression; a named group (?<name>pattern) says which part becomes which field. Default source: _raw; field= picks another.
      Why it exists
      Nobody wrote a sourcetype for every log in the world. rex lets the analyst build the field now, without touching props.conf.
      Where used
      Linux text logs, CEF, URLs, command lines — anything where the value sits inside free text.
      Example
      | rex "COMMAND=(?<cmd>.*)$" on sudo lines gives the command.
      SOC example
      NC-S4-01 (page 30) uses rex "from (?<src_ip>\d+\.\d+\.\d+\.\d+)" so Linux failures and Windows failures share one src column via coalesce. Session 3's regex playground was practice for exactly this.
      evalterm
      Definition
      Calculates a new field (or rewrites one) for every event from an expression: arithmetic, text, conditions, functions.
      Why it exists
      The question is rarely in the raw fields: "is it an error?", "LAN or internet?", "which hour?", "what is the second name?".
      Where used
      Before stats (to group by the new field) and after it (to compute percentages, thresholds, labels).
      Example
      | eval where=if(cidrmatch("10.0.0.0/8", src), "LAN", "internet")

      eval src=coalesce(Source_Network_Address, src_ip) — one field name for two platforms, so one alert covers both. Without it you would write two alerts and compare them by hand.

      1. Splunk = collect + index + search, in real time. Forwarder ships (UF forwards only, HF can parse first) → indexer parses and stores → search head asks. Free learns; Enterprise runs; ES is the SIEM app with six features.
