    Forensic science — evidence you can defend

    Forensics turns observations and data into reliable evidence for fact-finding.

    Forensic scienceterm
    Definition
    The application of scientific principles and techniques to investigate crimes and resolve legal disputes: collect, preserve, analyse and present evidence so it is legally admissible.
    Why it exists
    Courts and organisations need facts they can trust, not opinions. Science makes evidence objective and repeatable.
    Where used
    Forensic biology (DNA), chemistry (toxicology), ballistics, pathology — and digital forensics.
    Example
    A fingerprint on a door handle matched to a known suspect.
    SOC example
    A disk image, hashed at collection and again before analysis, proves the evidence you present is the evidence you collected.
    The core principle (INE)

    "Evidence must be collected and analysed in a way that maintains its integrity and avoids contamination or alteration."

    INE's worked case — four goals of the forensic process

    A suspicious death at home. Investigators secure the scene, collect fingerprints, fibres and a blood sample, then analyse them (fingerprint match, DNA, ballistics, toxicology). The process aims at reconstruction (the sequence of events), attribution (link evidence to a person), integrity & admissibility (it stands in court) and truth-seeking (an objective account). Digital forensics has exactly the same four goals.

    Keep this

    Integrity first: collect and analyse without changing the evidence.

    S09 · P06Theory⏱ 7 min

    Locard's Exchange Principle — every contact leaves a trace

    Dr. Edmond Locard, the father of modern forensic science: whenever two things touch, material passes both ways.

    Locard's Exchange Principleterm
    Definition
    Whenever two objects — or a person and an environment — come into contact, there is a mutual exchange of material (trace evidence).
    Why it exists
    It explains why a search for traces is worth doing: they exist, even when they are microscopic.
    Where used
    Physical forensics — and, as INE says, cyber incidents: "every action in a digital environment leaves a trace."
    Example
    A burglar leaves fibres on the broken window and carries glass away on his shoes.
    SOC example
    An attacker who logs in leaves failed logons and an unusual IP in the logs — and takes your data with him, which shows in the network logs.
    ▶ Name the traces — then check

    Pick an attacker action. Where would its traces be?

    Authentication traces

    Failed logons, an unusual source IP, an odd time of day — Security 4625/4624, VPN and SSH logs (Sessions 5–7).

    Host traces

    Registry modifications, dropped files, process-execution records, changes in memory — Sysmon 1/11/13, Prefetch, RAM.

    Network traces

    Large outbound transfers, unusual encryption or protocols, connections to C2 servers — firewall, proxy and flow logs.

    Traces of the deletion itself

    The deletion is an action too: 1102 when logs are cleared, NTFS metadata that outlives the file ($MFT, $UsnJrnl — page 22), copies already forwarded to a SIEM.

    Who came in.

    What ran.

    What left.

    Hiding is also a contact.

    Keep this

    Every action in a digital environment leaves a trace. If you have not found it, you have not looked in the right place — yet.

    What digital forensics is — and why it is done

    A sub-branch of forensic science, applied to data.

    Digital forensicsterm
    Definition
    Identifying, preserving, analysing and presenting evidence from digital devices and systems — forensic science applied to digital evidence.
    Why it exists
    To investigate incidents, support legal proceedings and understand security events with facts that hold up.
    Where used
    Law enforcement, corporate investigations, and incident response.
    Example
    A memory dump shows code injected into a server process.
    SOC example
    "Was data stolen?" — answered from disk, memory and network evidence, not from a guess.
    Digital evidence

    Any information with probative value (it helps prove something) that is stored or transmitted in digital form: log files, emails, memory dumps, disk images, network captures.

    Legal / criminal

    Cybercrime — hacking, fraud, identity theft, insider threats. Admissible evidence for prosecution.

    Organisational

    Data breaches, insider misuse, IP theft. HR and compliance investigations.

    Security / IR

    Root cause, attacker TTPs, scope and impact, intelligence to prevent recurrence.

    Keep this

    Same evidence, three possible audiences: the SOC, HR, a court. Collect it as if the court is next.

    S09 · P09Theory⏱ 6 min

    The role of digital forensics in incident response

    Forensics enables evidence-based decisions in every phase. Without it, IR risks being superficial: symptoms are fixed, but the attacker's foothold stays.

    IR phaseWhat forensics gives it
    Detection & AnalysisValidates alerts, reconstructs the attacker timeline, separates false positives from true incidents
    Containment & EradicationEvidence of persistence, rootkits and lateral movement — guides what to contain and remove
    Post-incident / RecoveryThe "how" and "why" — remediation, stronger defences, lessons learned
    Five things it gives responders
    • 1Root cause — how they got in.
    • 2Timeline — when it began, what was touched.
    • 3Impact — what data was accessed, changed or taken.
    • 4Remediation guidance — persistence and lateral paths to remove.
    • 5Evidence — defensible for legal, regulatory or internal use.
    INE's expectation

    Incident responders do not need to be full-time forensic analysts, but they must be able to apply forensic techniques quickly and effectively to support containment, eradication and recovery.

    Three incidents that need forensics

    A

    Phishing → malware

    1. Preserve the email — headers, attachment.
    2. Extract indicators — URL, attachment hash.
    3. Analyse the host — dropped files, persistence keys, C2 in logs.
    B

    Insider data theft

    1. Workstation — USB logs, file access times, browser history.
    2. File-server logs — what was copied.
    3. Correlate with email logs or DLP alerts.
    C

    Ransomware

    1. Initial vector — malicious document, RDP brute force.
    2. System + network logs — lateral movement.
    3. Encrypted hosts — notes, binaries, persistence; proof of exfiltration if double extortion.
    Keep this

    Root cause · timeline · impact · remediation · evidence.

    The digital forensics process — six stages

    A structured process makes an investigation accurate, repeatable and legally defensible. NIST, SWGDE and ISO word it differently; the core stages are the same.

    ModelStagesWhere you meet it
    NIST computer forensic processIdentification → Collection → Examination → Analysis → ReportingUS government and enterprise
    DFRWS modelIdentification → Preservation → Collection → Examination → Analysis → Presentation → DecisionAcademic and research; training
    Keep this

    Identify → preserve → collect → examine → analyse → report. DFRWS adds a final decision; NIST folds preservation into collection.

    S09 · P11Theory⏱ 8 min

    Law, authority and the six rules of evidence

    Responders are not lawyers — but they must know the boundaries, because their findings may end up in court.

    US cybercrime laws (INE)

    18 U.S.C. §1029 — fraud with access devices (cards, credentials, SIM-swapping). 18 U.S.C. §1030, CFAA (1986) — unauthorised access, exceeding authorised access, fraud and extortion, malicious code, damage such as ransomware. Most incidents you handle fall under the CFAA.

    Local note — Egypt

    Law No. 175 of 2018 on combating information-technology crimes, and the Personal Data Protection Law No. 151 of 2020. Same lesson: know which law applies, and what you may collect.

    Authority to collect

    Law enforcement usually needs a warrant or subpoena. In companies, consent and internal policy give authority — but stay in scope (no browsing through an employee's irrelevant personal files). Missteps can make evidence inadmissible and expose you to liability.

    The six rules of evidence

    1 · Admissibility

    Legally obtained and relevant. Outside legal boundaries → it may be excluded.

    2 · Authenticity

    Provably what it claims to be — hashes (MD5, SHA-256) plus the custody record.

    3 · Integrity

    The original stays unaltered. Examine copies; use write blockers.

    4 · Chain of custody

    Who collected it, when and where, how it was stored, who had access.

    5 · Relevance

    Directly related to the matter. Over-broad collection risks exclusion.

    6 · Reliability

    Scientifically reliable, accepted methods and tools. Untested tools can be challenged.

    In action

    Four practical expectations

    1 Know the legal scope · 2 follow forensic principles · 3 assume your findings will reach a legal or regulatory audience · 4 balance speed with defensibility — shortcuts (skipping documentation, changing timestamps) break investigations.

    Keep this

    Admissible · authentic · intact · tracked · relevant · reliable.

    Chain of custody — and your own form

    The chronological, documented record of evidence from the moment it is collected until it is returned, archived or destroyed. Any gap can get evidence excluded.

    Purpose
    • ·Integrity — not altered or tampered with.
    • ·Accountability — every person who controlled it.
    • ·Admissibility — courts need an unbroken chain.
    • ·Trustworthiness — confidence in the findings.
    What it involves
    • 1Documentation — unique ID, description, serial, date/time/place, collector.
    • 2Secure storage — evidence bags, sealed containers, digital vaults.
    • 3Transfer and access — every hand-over logged: who, when, why.
    • 4Verification — hashes prove nothing changed.

    Types and sources of digital evidence

    Know where to look and what each source can tell you — then collect only what answers your questions.

    Volatile

    Lost at power-off: RAM, running processes, network connections, encryption keys, clipboard.

    Non-volatile

    Persists: hard drives, SSDs, mobile storage, cloud data.

    Active

    In use now: files on the desktop, browser cache.

    Latent

    Hidden, deleted, residual: deleted files, slack space, unallocated space.

    Metadata

    About the data: timestamps, owners, geolocation, document properties.

    Network

    Logs and packet captures of communication between systems.

    SourceExamples
    Endpointsdesktops, laptops, mobiles, tablets
    Serversfile, web, email servers; domain controllers
    Network infrastructurefirewalls, routers, IDS/IPS, SIEMs
    Storage mediahard drives, SSDs, USB devices, backup tapes
    Cloud servicesOffice 365, AWS logs, Google Workspace, SaaS
    Applicationsdatabases, collaboration platforms, email clients
    Peripheral / IoTCCTV, printers, VoIP phones, industrial control systems

    Method evidence

    Impact evidence

    Identification — know what exists, where, and why it matters

    The first and foundational stage. Before you collect anything, you must know what evidence exists, where it resides and why it is relevant.

    What identification entails
    • 1Scope — the nature of the incident and the investigation goals.
    • 2Locate sources — endpoints, servers, mobiles, firewalls, cloud, databases.
    • 3Determine relevance — not everything: who, what, when, how.
    • 4Preservation awareness — spot volatile sources and prioritise them.
    What a responder must know
    • ·Systems involved and possibly compromised.
    • ·Evidence categories — volatile, non-volatile, external (cloud, SaaS, email).
    • ·Legal and policy — authority? PII, PHI, PCI data?
    • ·Incident context — type, business impact, questions.
    • ·Priority — volatile first, then persistent, then external.
    Identification in action (INE)

    A workstation behaves strangely after an email attachment. Scope: possible phishing → malware. Sources: workstation RAM, disk, the email server (headers + attachment), firewall logs. Priority: RAM first. Relevance: only logs and files tied to this user and system. Result: you know what to collect, in which order, and why.

    Keep this

    What exists · where it lives · why it matters · what disappears first.

    S09 · P19Theory⏱ 6 min

    Collection — in the order of volatility

    Acquire evidence so it stays preserved, complete and legally defensible — and make no change to the original.

    What collection entails
    • 1Acquire — volatile first, then images, then log exports.
    • 2Preserve integrity — write blockers, hash at collection, custody.
    • 3Follow procedure and law — validated tools, policy, GDPR, HIPAA.
    • 4Document — date, time, system, collector, tools, hashes, transfers.
    Forensic principles
    • ·Forensic images (bit by bit), not logical copies.
    • ·Never analyse originals — only verified copies.
    • ·Hash, and re-hash, to prove no tampering.
    • ·Confirm authority; respect privacy.
    CollectTools
    Disk imagesFTK Imager, EnCase, dd, Guymager
    MemoryFTK Imager, DumpIt, Belkasoft Live RAM Capturer (analysis later with Volatility — Session 10)
    Logs and network dataWindows event logs and Sysmon exports, tcpdump, Wireshark
    Common Windows itemsRAM dump · disk image · .evtx · hives (SYSTEM, SOFTWARE, NTUSER.DAT) · Prefetch · browser history · shadow copies
    Collection in action (INE)

    Same phishing case: capture RAM at once → image the disk through a write blocker → export the email and attachment from the mail server → collect firewall and proxy logs → hash everything (SHA-256) and fill the custody form. A complete, unaltered evidence set.

    Keep this

    Registers → RAM → connections → disk → logs. Then hash and document.

    Collecting volatile data by hand

    Built-in Windows commands give you a point-in-time snapshot of a live system — before anything is shut down.

    Why

    Preservation — sessions, users and system state are lost otherwise. Situational awareness — what runs, where it talks. Guides response — an active C2 connection or a rogue process changes your containment plan.

    When

    Early in live response · when no RAM tool is ready yet or the host must stay up · for quick triage · when shutting down is not an option.

    S09 · P22Tool⏱ 8 min

    Disk imaging — and the NTFS files that come with it

    A forensic image is a bit-for-bit copy of every sector — not just the files you can see.

    Disk imagingterm
    Definition
    Creating a forensic copy of an entire storage device at the lowest level: active files, deleted files and unallocated space, system areas (boot sector, MFT, partition tables), hidden data and slack space.
    Why it exists
    Working on the original risks changing or destroying evidence; a normal file copy misses everything that is not a visible file.
    Where used
    Every case that may need deep analysis or legal defence — and every dead-box investigation (Session 6).
    Example
    HR-WS07.E01 — an E01 image of the HR workstation's SSD, verified by MD5 and SHA-1.
    SOC example
    From one master image you make many working copies; analysts never touch the original.

    Logical (one volume)One partition, e.g. C:Large drives, only one volume matters
    Custom content (AD1)Selected files and folders onlyFast triage: hives, logs, LNK, Prefetch, recycle bin

    File hashing — the evidence fingerprint

    A hash is a fixed-length value computed from data. Change one bit and the value changes completely.

    Hash valueterm
    Definition
    The output of a mathematical algorithm (MD5, SHA-1, SHA-256) run over a file, disk image or memory capture — a fixed-length "checksum".
    Why it exists
    To prove data has not changed, and to recognise known files without opening them.
    Where used
    Collection, every transfer, before analysis, in the custody form and in court.
    Example
    Get-FileHash .\HR-WS07.E01 -Algorithm SHA256
    SOC example
    The IOC "SHA-256 of update.exe" in Session 7 is the same idea used for detection.
    Unique

    A tiny change — one flipped bit — gives a completely different hash.

    Deterministic

    The same input always gives the same hash.

    One-way

    You cannot rebuild the data from the hash.

    Three uses in forensics
    • 1Integrity — hash at collection, compare before every use; a mismatch means corruption or tampering.
    • 2Known files — compare with NSRL (known good) to skip system files and with known-bad lists to flag malware.
    • 3Chain of custody — the hash on the form proves the court sees what you collected.
    Commands
    Get-FileHash .\file -Algorithm SHA256   # PowerShell
certutil -hashfile file SHA256           # cmd
sha256sum file ; md5sum file             # Linux

    MD5 and SHA-1 have known collisions. Record SHA-256; add MD5 when a tool or partner expects it.

    Keep this

    Hash when you collect · hash before you analyse · match = authentic.

    File headers and magic numbers

    File-header analysis examines the first bytes of a file to find its true type — whatever its name says.

    Magic number (file signature)term
    Definition
    A fixed sequence of bytes at the start of a file (the header) that identifies its format. Some formats also have a fixed end (the footer).
    Why it exists
    Programs need to recognise a format from its content; the extension is only a hint for the user and for Explorer.
    Where used
    Triage of suspicious attachments and dropped files, file carving, finding disguised executables.
    Example
    report.pdf whose first bytes are 4D 5A ("MZ") is a Windows executable, not a PDF.
    SOC example
    A mail filter that blocks .exe but trusts extensions can be bypassed with a renamed file — the header still says "MZ".
    Why attackers change extensions (INE)

    To make a file look harmless to the user · to bypass filters that block only some extensions · to slow responders during triage. Some dropped files have no extension at all.

    Can an extensionless file run?

    Yes. Windows runs any file with a valid PE (MZ) header when it is started explicitly — from cmd.exe, PowerShell or a script. Only a double-click in Explorer fails, because Explorer relies on the extension.
