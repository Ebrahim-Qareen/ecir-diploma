    KQL filters documents. It has no pipe: counts come from the hit number, the fields list and Lens.

    Ask the room

    In SPL you wrote | stats count by host. Where does that go in KQL?

    Show the answer

    Nowhere. KQL only decides which documents match. The count is the hit number; "by host" is the field's top values or a Lens chart.

    What INE says
    • Kibana filters the data with KQL, the Kibana Query Language.
    • INE's threshold-rule example is also called "KQL" — that one is Kusto, Microsoft Sentinel's language. Same letters, two languages.

    KQL — two meaningsterm
    Definition
    Kibana Query Language: a filter for Discover, Lens and rules. Kusto Query Language: Microsoft's pipeline language for Sentinel and Defender.
    Why it exists
    Kibana KQL makes field filters short. Kusto, like SPL, also counts and groups.
    Where used
    Kibana KQL: Elastic. Kusto: INE's threshold example (slide 181), Sentinel, Defender XDR.
    Example
    Kibana: event.code:4625 · Kusto: | summarize count() by bin(TimeGenerated, 5m)
    SOC example

    What a detection rule is — six parts on one card

    A saved hunt plus a schedule, a threshold, a severity and a reason. NC-S5-04 shows all six.

    The detection pipelineNC-S5-05 · TTP · whoami run as SYSTEM · every 5 min over the last 5 min
    1Hunt2Rule3Alert4Triage5Case6IOC📒Rulebook
    Ask the room

    H8 is a saved search. What does it still need before it is a rule?

    Show the answer

    A schedule (every 5 min), a condition (any hit), a severity, an ATT&CK tag and a response — and an exclusion for NcMon.

    What INE says
    • A detection rule is logic in a SIEM, EDR or NDR that defines what suspicious activity looks like: a query or pattern plus a condition.
    • For responders it answers what happened, when and where — and starts the investigation.
    NC-S5-04ThresholdMany failed logons from one source Data: index=nc_wineventlog EventCode=4625 + index=nc_linux "Failed password" · Logic: per 5 min, per host + source: count > 10 or dc(user) ≥ 5 · Severity: medium · Response: Tier 1 checks for a success from the same source T1110.001 · T1110.003 · fired 3 times on night 1
    detection ruleterm
    Definition
    Saved logic — a query or pattern plus a condition — that a security tool runs to find suspicious activity.
    Why it exists
    Nobody can watch every log. A rule watches for one known shape, all the time.
    Where used
    SIEM (Splunk saved search, Elastic rule), EDR, network sensors.
    Example
    NC-S5-04: more than 10 failed logons, or 5 or more user names, from one source in 5 minutes.
    SOC example
    The same rule fired on the spray (12 names), the SSH brute force (16 fails) — and on an internet scanner (6 names). One rule, three stories: triage tells them apart.
    Keep this

    Data, logic, threshold, severity, ATT&CK, response — a rule card without one of them is a search, not a rule.
