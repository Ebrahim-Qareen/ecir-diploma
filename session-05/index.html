    Kibana search basics — Discover, fields and KQL

    Kibana is the window into Elasticsearch. Discover is where you search; Lens is where you chart.

    KQLMeansSPL you know
    action : "failed"field equals valueaction=failed
    status : 404 and src_ip : "193.106.191.22"both trueimplied AND
    not Source_Country : "United States"excludeNOT
    UserName : S*wildcardUserName=S*
    status >= 400rangestatus>=400
    file_hash : *field existsfile_hash=*
    KQL is not SPL

    KQL filters — it has no stats or | sort. Counting and charting happen in the field list (top values) and in Lens visualisations. Booleans are lowercase-friendly (and, or, not).

    Detection engineering

    What detection engineering is, the six types of detection rules, and the difference between a rule and an alert.

    Theory⏱ 3 pages · 30 min

    What detection engineering is

    The discipline that designs, builds, tests and tunes the logic behind every alert you will ever triage.

    What INE says

    Detection Engineering is the discipline of designing, developing, testing and refining detection logic that identifies suspicious or malicious behaviour. In IR it bridges threat intelligence, real-world attacks and actionable alerts — giving responders timely, relevant, high-fidelity alerts to detect adversaries early, minimise dwell time, and speed up triage and containment.

    Core skillIn practice
    Write and test rulesSPL, KQL, YARA or vendor languages; validate on real or emulated data (e.g. Atomic Red Team)
    Triage and FP reductionJudge relevance, context and noise; tune filters, thresholds and enrichment
    Incident → detection feedbackTurn incident lessons into new rules; run retrospective queries for past activity
    CollaborationPropose improvements to engineers and hunters; share TTPs and findings in usable form
    Keep this

    Build → test → deploy → tune → learn from incidents → build again. As a responder, you know what an alert really means because you know how it was built.

    S05 · P14Theory⏱ 12 min

    Six types of detection rules

    Detection rules are logic-based instructions that SIEM, EDR and NDR platforms use to find suspicious activity — the "what, when and where" of an incident.

    ▶ Open each rule type

    Each card shows what it matches, where it is used, and INE's example.

    Signature-based

    Matches known indicators — hashes, IPs, strings. Finds known malware, exploits and specific actor tooling.

    rule Suspicious_Mimikatz {
  strings: $a = "mimikatz"
  condition: $a
}
    Behaviour-based

    Watches sequences of actions that deviate from baselines — credential dumping, privilege escalation, lateral movement.

    if process.name == "lsass.exe" and parent.name != "winlogon.exe" then alert
    Heuristic / anomaly-based

    Statistics or ML find outliers in user behaviour, traffic or file access.

    Alert if data transfer exceeds 10GB/hour and user is not in IT group
    Threshold-based

    Fires when a count crosses a limit — DDoS, brute force, mass file deletion.

    FailedLogons
| where ResultType == "0x18"
| summarize count() by AccountName, bin(TimeGenerated, 5m)
| where count_ > 20
    TTP-based (ATT&CK-aligned)

    Matches tactics, techniques and procedures attributed to adversaries; gives ATT&CK coverage mapping.

    index=wineventlog EventCode=4688
| where New_Process_Name="*powershell.exe*" AND CommandLine="*EncodedCommand*"
    Correlation

    Combines several detections over time to catch multi-step attacks.

    Rule 1: phishing email delivered
Rule 2: unusual VPN login after the email
Correlation: trigger if both occur within 30 minutes

    Fast and precise — but blind to anything new.

    Harder to evade; needs a baseline.

    Finds the unknown; more false positives.

    Simple and effective for volume attacks — you met it in Session 4.

    Maps detections to ATT&CK coverage.

    The highest-confidence alerts in a SOC.

    Classify

    "More than 10 failed SSH logins from one IP in 5 minutes, then a success from that IP." Which two rule types is this?

    Show the answer

    Threshold (the count) inside a correlation (two events in sequence). Most strong rules combine types.

    Keep this

    Signature · Behaviour · Anomaly · Threshold · TTP · Correlation. Know one example of each — the exam uses INE's.

    ▶ Same rule, different verdict

    The rule fires twice. Decide each one.

    True positive → escalate

    Unusual user, hidden window, unknown domain, hash flagged. Malicious until proven otherwise.

    False positive → close with a reason

    Legitimate admin activity. Tune the rule: exclude the signed script or the internal server — and record why.

    Context made it real.

    Context made it benign — and gave a tuning idea.

    Keep this

    The rule is the same; the context decides. Enrichment is where Tier 1 earns its value.

    Alert noise is irrelevant, duplicate or false alerts that bury the real ones. These four words and seven criteria cut through it.

    Close — false positive

    Approved activity. Add a suppression so it stops arriving.

    Escalate

    Kill-chain stage: C2. Always escalate.

    Contain & resolve

    Low risk, playbook fix available — Tier 1 quarantines and documents.

    Escalate

    Benign + known → close.

    C2 → escalate.

    Fixable + low risk → resolve.

    Keep this

    IOC types — and the Pyramid of Pain

    IOCs are breadcrumbs: the digital traces attackers leave. Some are easy for them to change, some are not.

    What INE says

    An Indicator of Compromise (IOC) is a piece of forensic data that suggests an endpoint or network may have been breached. IOCs help answer: Has this system been compromised? What type of attack took place? What other systems might be affected? Detecting IOCs is reactive — but found while the threat is unfolding, they enable faster containment.

    Role of IOCs

    Detection — tools flag or block known threats · Triage — verify true positives (hash → known RAT) · Hunting & intel — pivot to related activity · IR & remediation — scope the compromise and block it.

    Why they fade

    Hashes, C2 domains, static IPs, registry changes and filenames are rotated or obfuscated by attackers, so their lifespan keeps getting shorter.

    TypeExamplesGood forLimits
    NetworkC2 IPs, phishing domains/URLs, odd ports, beaconingFirewall, IDS, proxy detection; blocking outboundIP rotation, fast-flux; encryption hides payloads
    FileMD5/SHA-1/SHA-256, suspicious paths, signing certs, size anomaliesBlocking known malware at scaleOne byte changes the hash; packing, polymorphism
    BehaviouralOdd logins, Word launching PowerShell, PsExec to many hosts, new persistenceNovel and insider attacks; hard to evadeNeeds baselines; more FPs if not tuned
    Keep this

    Network · file · behavioural. The higher on the pyramid you detect, the harder it is for the attacker to escape.

    📋 ELK, rules, triage, IOCs — on one screen

    Kibana
    • Data view → time picker → KQL → fields → Lens
    • field : "value" and not x : y
    • Elasticsearch 9200 · Kibana 5601
    Detection engineering
    • Build → test → deploy → tune → learn
    • Before · during · after the incident
    6 rule types
    • Signature · Behaviour · Anomaly
    • Threshold · TTP-based · Correlation
    Rule vs alert
    • Rule = what to look for
    • Alert = what to do when found
    Log → incident
    • Log → normalize → rule → event
    • → alert → Tier 1 → case → Tier 2
    7 triage phases
    • Intake/dedup · classify · enrich (~30 s)
    • Score (Impact × Likelihood) · decide
    • Case · document & hand off
    Accuracy
    • TP act · FP tune · TN fine
    • FN = silent failure, most dangerous
    Escalate on
    • Severity · asset · kill-chain stage
    • Regulation · rule confidence
    • Containment feasibility · SLA
    IOCs
    • Network · file · behavioural
    • Detect → extract → correlate → enrich → validate
    • Pyramid: hash < IP < domain < artefacts < tools < TTPs
    Tiers
    • T1: match · enrich · decide
    • T2: pivot · hunt · sandbox · new IOCs

    3. Six rule types; the strongest rules combine them (threshold inside a correlation).
